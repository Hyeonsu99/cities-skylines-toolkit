# 한국 저밀도 주거 전용 구역 조사

조사일 2026-11-19. 결론: 오피스 분류를 만든 실제 에디터 설정은 아직 확인되지 않았다. 먼저 기존 2×2 한 채를 저밀도 주거 프리팹으로 다시 구성해 입주를 검증한다. 최종 목표는 독립 한국 `ZonePrefab`을 참조하는 건물 팩이며, 자체 C# 로더는 에디터가 해당 구역을 직렬화·배포하지 못한다고 확인되기 전에는 만들지 않는다. 즉시 플레이용 대안으로 Real Zoning & Building Themes의 건물 선택을 시험할 수 있다.

## 1. 현재 저장소에서 확인한 사실

- `HandOff.md` 195~199행은 한국 집이 저밀도 사무지구에서 L1로 지어진 관찰과 바닥 깜빡임을 기록한다. 가져오기 당시 프리셋이나 저장된 프리팹 값은 기록하지 않아 어느 클릭이 원인이었는지는 확정할 수 없다.
- `cs2-kit/projects/korean-lowrise/house_core.py`의 `build_and_export`는 `K.export_asset(spec.name, 1, ..., lot=spec.lot)`을 호출한다. `cs2-kit/cs2kit.py`의 `asset_name`이 `_L1_2x2` 문자열을 만들고 메시·텍스처를 내보낸다. 이 경로에서 주거 구역 프리팹을 등록한다는 증거는 없다. 해당 프로젝트에 `generate.py`는 없고 시대별 진입점과 `house_core.py`가 있다. `building_spec_KoreanHouseA01.yaml`의 `zone: ResidentialLow`는 후보 설계 기록이며 이 export 호출의 구역 설정 인자가 아니다.
- M1.5 보고서 기준 A01, 70s01, 80s01, 90s01은 모두 L1 2×2 대표다. 36개 시드는 비교·기하 검사용이지 36개 배포 완료 자산이 아니다. 90s 셔터 가게는 외형이며 상업 기능이 검증되지 않았다. `output/<자산명>` 각각을 Assets Folder로 사용하고 `work/variety_assets`나 프로젝트 상위 전체를 선택하지 않는다.
- `work/subobjects.json`은 마지막 생성 자산의 화분 좌표 제안이며 자동으로 게임에 적용되는 게임 프리팹이 아니다. 개별 파일 `subobjects_<asset>.json`도 제안이다. Z-up, pivot 적용 좌표를 게임 에디터 축에 그대로 대입하지 말고 확인한다.
- `maps/tools/cs2_mod/SintanjinMapBuilder`는 `netstandard2.1`, `Game.dll` 등 설치 게임 Managed DLL 직접 참조, `IMod.OnLoad(UpdateSystem)` 및 `UpdateBefore`를 이용하는 별도 지도 생성 코드다. 특정 게임/SDK 버전 고정 정보는 csproj에 없고 구역 생성·패키징 예제도 아니다. 설치 게임 DLL과 패치별 호환성을 따로 확인해야 한다.

## 2. 오피스 오등록: 확인 가능한 원인과 수리

**확인된 경계:** FBX/PNG는 모델·재질이고 파일명 `_L1_2x2`, YAML의 `ResidentialLow`는 게임에 구역/레벨/lot을 설정한다는 근거가 없다. Asset Importer는 Project Root, Assets Folder, Prefab Preset을 따로 받으며 기존 프리팹의 설정을 복사할 수 있다. 따라서 잘못된 office 프리셋/복사 원본 또는 이후 건물의 구역 참조·용도 설정이 남아 있을 가능성이 있다. 다만 원본 프리팹을 보지 못했으므로 어느 항목이 실제 원인인지 단정하지 않는다. `SpawnableBuildingData`와 `BuildingPropertyData`는 런타임 데이터 명칭으로 조사·검사할 대상이며 이것이 에디터에 그대로 편집 가능한 UI 라벨이라는 뜻은 아니다. 출처: [공식 Asset Editor 개발일지](https://colossalorder.fi/news/development-diary-custom-assets/).

**복구 절차 (UI 텍스트는 게임 버전에 따라 다를 수 있음):**

1. 테스트용 새 에디터 프로젝트/자산 사본에서 문제가 난 자산을 열고, 원본을 덮어쓰기 전에 이름, 프리셋, 참조 Zone, lot, level, 주거 세대/오피스 속성의 실제 값을 기록한다. 복사 원본과 비교해 어떤 값이 오피스였는지 확인한다. 원본을 볼 수 없으면 원인은 미확정으로 남긴다.
2. 메인 메뉴 Editor → Asset Importer에서 Project Root와 개별 `output/KoreanHouseA01_L1_2x2` Assets Folder를 지정한다. Building/Spawnable growable 경로를 선택하고, 복사 기능을 사용한다면 **저밀도 주거용 2×2 L1** 원본을 선택한다. 공식 문서의 “Existing Prefab in Project”는 기존 프리팹 설정 복사이며 무조건 Residential을 자동 선택한다는 뜻이 아니다.
3. 장면에 배치해 프리팹 편집 화면에서 실제 표시되는 Spawnable/zone 참조를 저밀도 주거 원본의 NA 또는 EU low residential Zone으로 지정한다. `ZoneType`이라는 이름의 드롭다운이 반드시 존재한다고 가정하지 않는다. lot width/depth 2/2, spawn level 1을 별도 확인하고, 주거 가구 수·용도와 도로 보행 연결을 원본과 비교한다. 오피스 사업체/직장 속성이 남아 있으면 주거 템플릿으로 다시 복제해 재구성한다. 정확한 필드명은 해당 빌드 UI 및 프리팹 검사로 확인한다.
4. 저장 후 새 테스트 도시에서 해당 NA/EU 주거 구역만 2×2로 칠하고 주거 수요·도로·전기·물 조건을 맞춘다. 개발자 도구/프리팹 검사로 건물 이름, 실제 zone reference, level, 가구 입주를 확인한다. 사무 구역에서도 출현하면 중복된 이전 office 버전·같은 ID 캐시를 점검한다. 필요하면 기존 잘못된 건물을 철거하고 저장/재로드 후 반복한다. 동일 화면 이름만으로 주거를 판정하지 않는다.
5. 결과가 확인되면 나머지 세 대표에도 같은 설정을 적용한다. 단순 재가져오기가 기존 프리팹 메타데이터까지 초기화한다고 가정하지 않는다. 기존 저장 자산 수정 및 새 ID 복제 중 무엇이 구독·세이브에 반영되는지 테스트한다.

## 3. 바닐라와 분리하는 방법

| 방법 | 확인된 기능과 한계 | 난도/유지보수/배포 |
|---|---|---|
| A. 같은 바닐라 Zone + 자산 팩 | 공식 에디터로 커스텀 자산과 팩을 만들고 PDX Mods에 공유할 수 있다. 기존 NA/EU 저밀도와 같은 zone 참조를 쓰면 팩 이름만으로 성장 후보가 한국 건물로 제한된다는 근거가 없다. 기본 UI에 그런 독점 필터가 있다는 것도 확인하지 못했다. | 낮음 / 패치 관리 적음 / PDX 배포 가능. 혼합 방지 목표 미충족. |
| B. 독립 한국 ZonePrefab + 한국 건물 | 공식 [Region Packs](https://www.paradoxinteractive.com/games/cities-skylines-ii/modding/cities-skylines-ii-region-packs)는 신규 구역을 제공한다. 별도 한국 구역 ID만 건물이 참조하고 바닐라 건물은 이를 참조하지 않도록 만들면 분리가 목표다. 에디터 저장과 실제 성장 판정은 실험해야 한다. | 중~높음 / 안정적 식별자와 버전별 테스트 필요 / 에디터 직렬화 가능하면 자산 팩 우선, 불가능하면 코드 모드 검토. |
| C. 선택 모드 활용 | [Real Zoning & Building Themes](https://mods.paradoxplaza.com/mods/167314/Windows)는 제작자 설명상 팩·개별 건물을 선택해 새 구역을 칠할 수 있다. 2026-11 신규 모드이므로 버전, 저장 호환, 공유 가능한 설정과 L1~L5 동작은 실제 테스트가 필요하다. [제작자 설명](https://www.reddit.com/r/CitiesSkylines2/comments/1xusekg/new_mod_real_zoning_building_themes/). | 낮음~중 / 외부 코드 모드 업데이트 의존 / 구독자도 해당 모드 필요. 빠른 개인 테스트에 적합. |

[Asset Packs Manager](https://github.com/CitiesSkylinesModding/CS2-AssetPacksManager)는 작성자 문서상 현재 PDX 자산의 필수 로더가 아니라 플레이셋·레거시 썸네일/현지화·누락 보고 지원 도구다. 전용 성장 필터로 취급하지 않는다. [Zone Organizer](https://github.com/Mimonsi/CS2-ZoneOrganizer)는 주거 탭을 밀도별로 재정리하며 독립 성장 후보 집합을 생성하는 도구라는 근거는 없다. ExtraAssetsImporter도 이름만으로 독립 Zone 생성기라고 볼 수 없다.

### B의 구체적 구조와 검증 경계

목표 구조는 `KoreanLowResidential` 고유 zone 프리팹 → 주거 분류·밀도·색·아이콘/UI 항목 → 해당 zone을 참조하는 L1~L5 건물 프리팹 → 각 메시/텍스처와 소품 의존성 → 에디터가 생성한 메타데이터와 PDX 패키지다. 구역을 노출하는 브러시/UI 등록과 저장·재로드가 필수다. 건물은 실제 주거 속성과 함께 동일한 zone ID를 참조해야 하며 바닐라 건물에 해당 ID를 부여하지 않는다. 같은 이름의 별도 zone 복제본을 자산마다 만들지 말고 공통 참조와 안정적 ID를 검증한다.

유저 제작 ZonePrefab 배포의 실례로 PDX 공개 플레이셋에 [UK Row Homes (Zone Prefab)과 UK Row Home Pack](https://mods.paradoxplaza.com/playsets/cities_skylines_2/11257728)이 별도로 열거된다. 이 목록만으로 내부 파일, 의존성, 성장 로직을 알 수는 없다. [Prefab Maker](https://qstar-inc.github.io/cities2-PrefabMaker/)는 Zone Prefab 생성 메뉴 및 게임 생성 `.Prefab`/`.Prefab.cid`를 기술하지만, 그 자체가 공식 지원 방식이나 현 버전에서 해당 팩이 그대로 동작한다는 증거는 아니다. 오래된 [커뮤니티 에디터 절차](https://www.reddit.com/r/CitiesSkylines/comments/1egmk96/)는 기존 구역의 Duplicate Template과 건물 저장을 제안한다. 현재 버전에서 직접 성공하기 전까지는 실험 가설이다. 공식 일본·중국·동유럽 팩의 JSON/C# 로더 내부는 이번 조사에서 확인하지 못했다. 따라서 해당 팩이 특정 오픈소스 로더를 쓴다거나 모든 ZonePrefab에 자체 C#이 필수라고 단정하지 않는다.

실험 순서: 저밀도 주거 Zone을 에디터에서 복제 → 이름/아이콘/UI/고유 식별자 확인 → 건물 사본의 zone 참조를 새 것으로 변경 → 저장 후 프로젝트 재개방 및 클린 플레이셋에서 구역 브러시와 성장 확인 → 두 번째 건물에서 같은 zone 참조 확인 → 패키지 의존성과 재구독 검증. 직렬화/브러시 노출이 실패하면 그때 설치 버전의 게임 API와 실제 로더 소스를 확인해 `IMod`/`PrefabSystem` 등록, 로드 순서, localization/icon, 저장 ID, 제거/갱신을 구현한다. 컴파일 가능한 검증된 API 시그니처는 아직 확보하지 못했으므로 추측 코드를 배포하지 않는다.

## 4. 성장 단계와 부지 제작 매트릭스

`_L<level>_<W>x<D>`는 **이 저장소 생성기의 명명 규칙**이다. 이름을 바꾸는 것만으로 레벨이나 lot이 설정되는 공식 규격이라고 확인되지 않았다. 실제 프리팹에서 width/depth/level/zone을 각각 지정한다. 셀 8 m 기준 2×2=16×16 m, 2×3=16×24 m, 3×2=24×16 m, 3×3=24×24 m. 폭은 도로 전면, 깊이는 도로에서 안쪽으로 확인한다. 20칸은 제안된 최소 커버리지이지 게임이 모든 크기를 요구한다는 뜻이 아니다.

| lot | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| 2×2 | 기존 70s01 | A01 파생 | 기존 80s01 파생 | 기존 90s01 주거형 | 정비된 벽돌·기와 파생 |
| 2×3 | 70s 길쭉한 마당 | A01 후면 증축 | 80s ㄱ자 | 90s 주거형 | 다가구 외형·마당 축소 |
| 3×2 | 70s 넓은 전면 | A01 좌우 확장 | 80s 넓은 발코니 | 90s 주거형 | 다가구 외형·전면 정비 |
| 3×3 | 70s 본채·마당 | A01 별채 외형 | 80s ㄱ자 | 90s 다가구 외형 | 정비된 다가구 외형 |

표의 기존 자산도 현재 모두 L1 2×2이므로 L2~L5 및 다른 크기의 칸은 **새로 제작·설정해야 할 제안**이다. 다가구 외형이 여러 세대로 작동하는지 저밀도 zone의 세대 규칙을 시험하고, 상점 외관만으로 mixed 상업 기능을 주장하지 않는다. 1단계 2×2의 5레벨을 먼저 만들고 2×3 → 3×2 → 3×3 순으로 늘린다. 각 칸 한 개면 20개 프리팹이고 변주 추가 시 더 필요하다. 똑같은 메시의 레벨 복제는 임시 검증용으로만 사용하고 각 단계의 설정과 시각 변화를 확인한다.

독립 zone에 바닐라가 참조되지 않는 것이 비혼합 조건이지, 20개를 채우는 것 자체가 비혼합을 보장하지 않는다. 누락된 크기/레벨에는 후보 부족·성장 정지 또는 다른 크기 선택이 가능하다. 게임의 모든 폴백/업그레이드 규칙은 미검증이므로 빈 칸이 바닐라로 자동 대체된다고도, 절대 대체되지 않는다고도 단정하지 않는다. 좁은/깊은 도로변, 2×2만 가능한 곳, L1→L5 승급 및 저장 재로드를 각각 관찰한다. 경제·서비스·수요 조건도 맞춘다. Signature 건물은 플레이어가 직접 놓는 별도 고유 건물이며 자동 성장 세트의 대체물이 아니다. [공식 구역·시그니처 설명](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/zones-signature-buildings).

## 5. 마당 z-fighting과 에디터 표면

1. 깜빡이는 면이 생성 메시의 포장인지 lot/지형/다른 데칼인지 에디터에서 각각 숨기거나 분리해 확인한다. `house_core.py` 각 LOD의 해당 마당 면을 함께 조사한다. 현재 관찰만으로 특정 면의 정확한 높이는 확정되지 않는다.
2. 권장: 메시에서 지형과 겹치는 넓은 마당 포장을 각 LOD에서 제거하고, Editor Asset Browser의 적합한 Surface를 polygon 도구로 부지 안에 그린다. 공식 개발일지는 자유형 표면 그리기와 `Binds overlapping items to a building` 스냅 옵션을 설명한다. 건물에 결속되는지 저장→에디터 재개방→게임 배치로 확인한다. Surface/Area의 항목명과 결속 지원은 버전별로 확인하며, 장식용 surface와 보행용 pathfinding area를 혼동하지 않는다. [공식 개발일지](https://colossalorder.fi/news/development-diary-custom-assets/).
3. 화분·식생은 해당 `subobjects_<asset>.json` 좌표를 참고해 내장 소품을 수동 배치하고 결속한다. 축·스케일·회전·경사 부지·LOD 전환을 검증한다. 외부 표면 팩이면 의존성을 명시한다.
4. 메시 포장을 유지해야 한다면 겹치는 면을 제거하거나 높이를 소량 조정해 평지·경사·원거리에서 시험한다. 임의의 수 cm 오프셋이 모든 지형에서 해결된다고 보장하지 않는다. 도로 접합부에 뜬 틈이나 지형 관통이 없는지 확인한다.

## 6. 실행 로드맵 및 완료 기준

1. 오등록 자산의 실제 프리팹/스크린샷을 확보하고 오피스 참조와 주거 복제 원본을 비교한다.
2. 2절대로 A01을 임시 주거 사본으로 재설정한다. 주거 구역 성장·입주·오피스 비출현을 확인한다.
3. 마당 원인 면을 식별하고 Surface 결속 및 저장/재로드를 확인한다. 본 작업은 조사만 수행했으며 메시를 수정하지 않았다.
4. 독립 zone의 에디터 복제·저장·공통 참조·브러시를 최소 1개 건물로 실험한다. 성공하면 에디터 기반 B를 채택한다. 실패하면 원인과 게임 버전을 기록하고 C 또는 최소 C# 로더의 필요성을 판단한다.
5. 2×2 L1~L5를 만들고 각 레벨 승급을 검증한 다음 나머지 lot 세트를 생산한다. 실패 시 후보·수요·세대·연결을 분리해 진단한다.
6. 클린 플레이셋에서 바닐라 구역과 한국 전용 구역을 나란히 테스트하고, 저장·재로드·업데이트·의존성 누락·PDX 재구독을 검증한다. 실제 결과를 기록한 뒤에만 전용 구역 완성 및 비혼합을 선언한다.
